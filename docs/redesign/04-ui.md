# 界面：作为 Harness 的一部分，而不是一个网站

## 原则

1. **先选渲染面，再写视图。** 选错面之后怎么调 CSS 都救不回来（官方 practices 的原话）。
2. 只用主题令牌 `--dsw-alias-*`；字面颜色只允许出现在**美术素材**里。
3. 不 iframe、不写 `document.body`、不 require 宿主的 UI 组件包（会随版本变）。
4. 组件内任何抛错会**清空整个插槽条目** → 每个注册组件必须有顶层兜底。
5. 文案全部走 Client locale 服务；`locale/zh.json`、`locale/en.json` 同步。

## 插槽分工（建议）

| 插槽 | 放什么 | 为什么 |
| --- | --- | --- |
| `sidebar.panellist` | 「鲸屿」全局入口（侧栏一行，点击进面板） | 与其它插件入口同级，用户能找到 |
| `sidebar.right.pane.tab` | 房间视图（像素画布 + 快捷操作） | 右侧栏本就有"标签页"概念，可常驻、可关闭 |
| `settings.section` | 设置页（人设、房间文件路径、外部记忆、主动生活） | 宿主设置框架的既有分区模式 |
| `conversation.chat.node` | （可选）对话内嵌的房间快照行 | 让"共同经历"出现在对话流里 |
| `shell.overlay` | （仅当确需）角色气泡/通知 | 需要全局悬浮时才用 |

**M0 只做 `settings.section` + `sidebar.panellist`。** 先把"能装、能开、能存"跑通，再做房间渲染。

## 房间渲染

- 首选 **Canvas 2D**（旧版已验证的等距像素投影逻辑在 `shared/isometric.js`、`shared/motion.js` 里是纯函数，可直接搬进 `world/`）。
- 渲染组件只接受 `{ room, viewport, onPick }`，**不碰业务**。
- 缩放/平移是纯视图状态；不得因视图变化重新发布布局。
- 像素缩放用 `image-rendering: pixelated` + 整数倍缩放，避免半像素模糊。

## 交互模型（与旧版的关键差异）

旧版：点击家具 → `app.action` → 后端校验 → 回传 → 重建场景（容易迟到结果覆盖新状态）。
新版：

1. 点击 → 组件内**乐观**高亮；
2. 调 Host 同一个 action 方法；
3. 返回 `{ok:false, reason}` 时回退高亮并显示原因；
4. 成功 → 等投影 `onChanged` 推送，用新状态重绘（**单一更新通道**，不再手工重建）。

即：**视图永远跟随投影，不跟随响应**。

## 可访问性与手感

- 所有可点元素是真实 `<button>`/`role="switch" aria-checked`，Escape 关闭弹层，焦点回收。
- 键盘可达：房间网格用方向键移动选择框。
- 减少动效：尊重 `prefers-reduced-motion`。
- 文案避免情感勒索式的催促（产品原则）。

## 验收（视觉部分）

安装后必须实机确认：
1. `meta.title`/`meta.description` 在插件列表与详情里显示正确（中英各一次）。
2. 图标实际渲染（不是默认灰图）。
3. 深浅色切换下房间与设置都不"发灰"（说明用的是令牌而不是写死颜色）。
4. 关闭/卸载插件后，插槽条目消失且无残留 DOM。
5. read-only 会话下房间编辑按钮为禁用态并给出原因。

**"装上去了"不等于"用户看到了"。** 未做浏览器实测前，只能报告"已安装、已注册插槽"，不能声称视觉验收通过。

## 美术与素材规则（沿用旧版已确认部分）

- 像素尺寸、帧数、锚点等规格**未经样板验证不写死**（旧版 AGENTS.md 的规则，继续有效）。
- 家具定义保持声明式：`definition.js` + `manifest.json` + 素材，不执行第三方代码。
- 内容包只允许受限的像素矩形与调色板，不允许任意代码（旧版已做，保留）。
