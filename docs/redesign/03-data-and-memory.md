# 数据、房间与记忆

## 决策：房间的存储形态

**建议：房间 = 工作区内的 JSON 文件（`world/room.json`），运行时缓存 = storage domain。**

理由：
- DSH 的核心承诺是"会话日志是唯一事实源"；但**房间布局不是对话产生的**，它更像项目文件，应该可读、可 diff、可 git、可被 agent 用 `read`/`edit` 直接改。
- storage domain 适合"插件私有索引/缓存"，用 zod 校验、可 backup-and-skip；把用户的家放进去，用户就再也看不见它了。
- 工作区文件天然获得沙箱保护（workspace-write 内可写，越界拒绝）。

风险与对策：
- 沙箱在 read-only 会话下**拒绝写入** → 房间编辑在 read-only 下必须只读展示，并在 UI 明说原因。
- 多会话共享同一工作区 → 房间文件是共享真源，写操作要 `fs` 的版本守卫（读-改-写带版本，冲突则重读重试）。

## 数据分层

| 数据 | 位置 | 生命周期 | 用户可编辑 |
| --- | --- | --- | --- |
| 房间布局（家具/墙/地板） | `world/room.json` | 持久，随工作区 | ✅ 直接改文件 |
| 初始人设（基线） | `world/persona.json` | 持久 | ✅ 但改动需确认 |
| 短期对话 | DSH 会话日志 | 随会话 | 由 DSH 管理 |
| 成长（兴趣/里程碑） | 会话投影（派生） | 随会话 | 只能"撤销到某点" |
| 角色外观/服装 | `world/room.json` 或资产包 | 持久 | ✅ |
| 外部记忆 | Hindsight（可选） | 外部 | ✅ 经工具/UI |

**明确不做**：不再有"插件自建长期记忆库"。旧版这一点做对了，保留。

## 人设是基线，不是可覆盖状态

- `persona.json` 是用户设定的**边界**；成长只能在其内变化。
- 任何"AI 自己改人设"的路径都不存在：没有对应工具。
- 修改人设是**用户专属动作**，模型只能提议（提议作为普通文本/工具结果，不落盘）。

## 成长：从 fold 到可见

1. `apply(state, event)` 消费：用户消息、助手消息、`tool/result`、`agent/inbox/spliced`。
2. 派生：兴趣权重、最近活动、里程碑（都是纯计算，无 IO）。
3. 反思（需要 IO 的部分）：由**工具** `dsh_world_reflect` 触发 → 调外部记忆或模型 → 返回结构化结论 → 结论作为 tool result 进日志 → 下一次 fold 吸收。
4. 撤销：给定上限 seq，重新折叠到该点（`stateVersion` 不变，仅游标变化）→ 天然可撤销，无需自建 undo 栈。

这解决了旧版最难的两件事：**"撤销成长"** 和 **"证据可追溯"**——证据就是日志里的 event seq。

## 记忆主库决策

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| A. 会话日志为主，Hindsight 可选 | 零外部依赖，fork/回放天然一致 | 长期跨会话记忆需靠 session-query 检索 |
| B. Hindsight 为主（旧版） | 长期记忆强 | 外部服务不可用即"失忆"；数据在插件外 |
| C. 双写 | 能力强 | 一致性难保证，易出现两套事实 |

**建议 A**：默认无外部记忆也能完整工作；用户开启 Hindsight 后，仅作为 `dsh_world_reflect` 的**后端**，写入仍以日志中的工具结果为准。
→ 好处：外部服务挂了，插件表现为"这次没反思"，而不是"失忆"或"编造"。

## 迁移（旧存档 → 新文件）

旧 `state.json`（schemaVersion 2，含 rooms/items/packs/life/growth）需要一个**一次性只读导入器**：

1. `dsh_world_import_legacy`（用户触发）读取旧文件，**不修改**旧文件。
2. 产出 `world/room.json` + 一份 `world/migration-report.json`（哪些字段保留、哪些丢弃、为什么）。
3. 旧版的自建成长/记忆索引 **不迁移**——它们本就该由日志重建；报告里明说这一点，而不是假装保真。
4. 失败即中止并保留原文件；不自动覆盖。

## 体积与素材

旧包内置 `assets/`（角色图集、家具 PNG、字体）与 `releases/*.tgz`（历史发布包）。新包应：
- 只保留运行必需素材；字体走系统或按需下载；
- **删除 `releases/`**（12 个历史 tgz + sha256），它们是仓库垃圾不是运行资源；
- 素材用 `files` 白名单精确控制。
